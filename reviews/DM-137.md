# DM-137 author security and release review

Issue: AlterMundi/daimon-matrix#137  
Base commit: `2c7f8017643ccd16f08d8f0a37e715496b5c0643`  
Review mode: owner-directed author self-review, followed by exact-head CI and release gates

## Scope

This review covers mandatory Telegram visibility for every Matrix external effect, exact operation/echo binding, owner-signed ambiguous retry, immutable carrier generations, runtime installation, schema migration, daemon lifecycle, route and peer transports, upgrade validation, conformance evidence, and packaging inclusion.

## Direct-effect inventory

| Seam | Durable admission | Final gate | Native effect | Ambiguity handling |
| --- | --- | --- | --- | --- |
| Telegram visibility | `EchoJournal._admit()` inside caller-owned transaction | `MandatoryEcho._current()` under the shared execution fence | installed `EchoTransport.send()` only | no authenticated response leaves `response=None`; retry requires one exact owner-signed command |
| Route provider request | route outbox attempt and registered native request | `MandatoryEgressController.release_registered()` | `AuthenticatedProvider._round_trip` | connection, egress, malformed or unauthenticated response becomes `RouteAmbiguous`; stable request bytes are retained |
| Peer request | `PeerOutbox.get_or_create_carrier()` | controller release plus current authority/endpoint/credential revalidation | configured peer round trip | connection, invalid HTTP contract, invalid envelope, or wrong authenticated response becomes `PeerTransportAmbiguous`; carrier bytes remain stable until expiry |
| Route/peer response | receiver intake and response stored before release | controller release with exact catalog/path/locator/native digest | response carrier | repeated request resolves to the stored exact response; handler effect is not repeated |

No production caller invokes provider `deliver()` directly. `RouteCoordinator` deliberately calls the unbound `AuthenticatedProvider.prepare_submission()` and `send_prepared()` implementations, so provider overrides cannot bypass the controller. Synthetic visibility is confined to explicit `synthetic_*` drivers and test fixtures; runtime and daemon entrypoints require an installed owner-authenticated visibility controller or fail closed.

## Mandatory gate checklist

1. **Authoritative discovery:** PASS. All route, peer, response, and Telegram seams were inventoried across `src/`; controller registration covers each exact path.
2. **Atomic admission:** PASS. Logical operation and echo obligation are committed through the caller-owned SQLite transaction; fault-injection tests cover every admission boundary.
3. **Exact binding:** PASS. Catalog, path, locator, native digest, projection digest, echo operation, echo binding digest, authority head, deadline, and runtime/application installation are checked.
4. **Migration/compatibility:** PASS. Normal open validates without DDL; explicit migrate mode owns schema repair. Legacy runtime upgrade validation is isolated and only falls back when the exact new module is absent.
5. **Lifecycle:** PASS. Registry closure and recovery precede listeners and READY; the bounded worker advances echo only and never releases Matrix native effects.
6. **Ambiguity:** PASS after findings F-3/F-4 below. Telegram ambiguity requires owner authorization. Route and peer ambiguity retain stable carrier bytes and rely on receiver-side durable deduplication.
7. **Carrier immutability:** PASS. Pre-expiry retries reuse exact bytes; expiry creates a new generation without rewriting history.
8. **Final revalidation:** PASS. Current authority, endpoint identity, target credential/embodiment, policy, application/runtime installation, and exact native bytes are checked immediately before release.
9. **Controller authenticity:** PASS. Production visibility installation verifies owner and participant bindings, disclosed destination, acceptance set, policy, secret references, Telegram qualification, application digest, runtime identity, and bot identity.
10. **Packaging:** pending final release gate. Source declarations include the new runtime module; sdist/wheel content and isolated installation must pass before merge.

## Findings resolved in the candidate

### F-1 — Upgrade validator could borrow modules from the current checkout

Severity: high. A staged candidate could be validated with imports from the current package. The validator now copies and imports the candidate in isolation, uses closed visibility when the module exists, and permits legacy fallback only for exact absence of `daimon_matrix.native_egress`.

### F-2 — Recovery and synthetic test loaders omitted mandatory visibility

Severity: high for recovery availability. Recovery composition now uses `closed_visibility()` explicitly; synthetic tests opt into `synthetic_visibility()` explicitly. Production defaults remain fail closed.

### F-3 — Route effect with unauthenticated response was misclassified

Severity: high. A provider could admit the request and return corrupt bytes; validation occurred outside the ambiguous-effect boundary and raised non-retryable `RouteError`. Validation and response retention now occur inside that boundary, producing `RouteAmbiguous`. The HTTP integration test proves identical prepared bytes are retried and receiver intake occurs once.

### F-4 — Peer effect with invalid HTTP/envelope response was misclassified

Severity: high. Invalid post-POST status/headers/body or an invalid authenticated peer envelope could be reported as ordinary `PeerTransportError` after a possible remote effect. These cases now produce `PeerTransportAmbiguous`. The restart test proves a lost response followed by a corrupt response reuses identical ciphertext and executes the receiver handler once.

## Broad-exception review

Broad catches in the affected security boundary were classified individually. They only sanitize untrusted parsing, roll back storage, convert authorization failures to deny, or preserve ambiguity. None creates an operation, confirms echo, manufactures a permit, retries an ambiguous Telegram post, or invokes a native carrier after failure.
