## Finding resolved in the candidate

The real succession retained the exact old response in the durable RPC journal
and produced no duplicate event, but the restarted daemon rejected that cached
response because it compared the response server only with the active origin.
The client had the same single-origin assumption. The resulting closed
connection was safe but violated the exact-retry contract.

The repair verifies a cached response against its own authenticated server
origin after proving that origin belongs to the accepted authority history and
the same body, embodiment and principal as the active server. Client config V2
names a sorted, unique, bounded set of historical origins with retirement
milliseconds. A historical response is accepted only for a request issued at
or before that retirement; ordinary new work still requires the current
server. Config V1 remains the unchanged single-incarnation profile.

Focused tests prove byte-identical replay after an authority epoch, no duplicate
event, rejection after retirement and rejection of a historical origin with a
different principal. Static typing, formatting and generated-fixture checks
also pass. The broad source suite passes all Matrix behavior; its only initial
failure was the deliberate exact-commit Cluster contract because the ordinary
sibling checkout had advanced. Re-running that contract against the pinned
Cluster commit passed.
