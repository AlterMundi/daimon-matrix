# DM-083 two-host dogfood candidate self-audit

Date: 2026-08-10

Verdict: **LIVE SAME-BEING PATH EXERCISED; SUCCESSOR RETRY REPAIR REQUIRES
EXACT-CANDIDATE REDEPLOYMENT BEFORE ACCEPTANCE**.

## Scope

This audit covers issue #111 and draft PR #112 under the accepted coordination
claim. The operator explicitly authorized reversible work on Legion and the
daimonmatrix host. No endpoint, custody path, secret, private message content or
credential value is published here.

The session exercised a fresh root-bound being across two existing host
embodiments, native encrypted Matrix peer exchange, `/me` and `/we`, pending
intake, observer-local adoption/reversal, same-incarnation exact retry, peer
outage, portable restore, encrypted off-host backup, one separately accounted
Tribe v1 message and one root-authorized incarnation succession.

## Finding resolved in the candidate

The real succession retained the exact old response in the durable RPC journal
and produced no duplicate event, but the restarted daemon rejected that cached
response because it compared the response server only with the active origin.
The client had the same single-origin assumption. The resulting closed
connection was safe but violated the exact-retry contract.

The repair verifies a cached response against its own authenticated server
origin after proving that origin belongs to the accepted authority history and
the same body, embodiment and principal as the active server. Client config V2
names a sorted, unique, bounded set of historical origins with retirement
milliseconds. A historical response is accepted only for a request issued at
or before that retirement; ordinary new work still requires the current
server. Config V1 remains the unchanged single-incarnation profile.

Focused tests prove byte-identical replay after an authority epoch, no duplicate
event, rejection after retirement and rejection of a historical origin with a
different principal. Static typing, formatting and generated-fixture checks
also pass. The broad source suite passes all Matrix behavior; its only initial
failure was the deliberate exact-commit Cluster contract because the ordinary
sibling checkout had advanced. Re-running that contract against the pinned
Cluster commit passed.

## Operational and authority conclusions

- The two processes are embodiments of one being, not a relationship between
  two beings.
- Cluster owns service/storage/effect lifecycle only. It did not create or
  interpret identity, `/we`, adoption or message authority.
- Peer import did not adopt; the decision and reversal stayed observer-local.
- The Tribe ACK/dedup result is transport evidence only. Matrix logical
  recipient intake and a signed semantic receipt remain a later live gate.
- The successor epoch changed only one embodiment lane and preserved all
  accepted history.
- Snapshot and backup evidence is recoverable and checked, but final offline
  root/recovery escrow still requires separate physical/governance custody.

## Remaining gate

This candidate is not yet the final DM-083 acceptance record. Freeze its exact
commit, repin and verify Cluster, deploy that exact release to both runtimes,
configure the retired Legion server origin locally, and retry the preserved
request. Acceptance requires the original response hash, no event-count change,
and converged successor heads. Matrix PR #112 also retains its independent
review requirement; this self-audit does not satisfy that external gate.
