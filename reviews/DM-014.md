## Normative design

- **Stable lineage:** `species_id` derives from one self-certifying genesis
  core. Every signed release has a distinct content-derived
  `species_release_id`; neither rewrites `/me` or `/we`.
- **Genome boundary:** foundation `/me` definition, contracts, protocol bounds,
  conformance suites, compatibility requirements, and invariants are required
  and non-empty. Identity, history, memory, keys, grants, membership, leases,
  routes, and harness state are excluded.
- **Maintainer authority:** dedicated Ed25519 keys authorize only typed species
  genesis/releases. The exact predecessor policy authorizes rotation; every
  initial or replacement key proves possession under the enclosing DM-011
  artifact domain; immutable policy floors prevent silent weakening.
- **Deterministic compatibility:** closed content-addressed WASI bundle, runner,
  suite, invariant, input/result, dependency, and resource schemas make checks
  independently executable. Requirements ratchet monotonically, and large
  result sets use bounded CAS pages committed by the release.
- **Fork safety:** occupied positions are retained. No arrival, timestamp,
  semantic version, length, or hash chooses a sibling. Specialized
  threshold-authorized epoch closure uses an explicit paged manifest and can
  recursively resolve resolution forks without erasing old evidence.
- **Single parent chain:** a branch declaration is a compatible no-op release
  in the parent's sole release chain. Concurrent declarations/successors are
  therefore ordinary deterministic forks, not arrival-ordered side effects.
  The signed foundation binds exactly one child nonce, genome, bundle, policy,
  floor, typed breaking deltas, and paged incompatibility evidence.
- **Incoming/application:** `/species.incoming` is a side-effect-free,
  content-bound, paginated local projection with a total five-state taxonomy.
  Application uses portable verification manifests, exact local policy/runtime
  refs, a signed per-identity event chain, a fenced recovery journal, and
  persistent capability-broker confinement after activation.
- **Authority boundary:** species and application artifacts never authorize
  identity control, `/we`, birth, source/tribe grants, routes, disclosure,
  memory, or body capabilities. `diverged`, `incomplete`, and `quarantined`
  identities do not resolve as `/species` recipients.

## Birth and legacy-vector boundary

DM-013 birth offers and acceptances require the exact typed DM-014 release ID.
The objective anti-downgrade floor is the parent's immutable enrollment
release, so a later compatible update cannot retroactively invalidate a
historical offer.

DM-010 retains `species_release_id = string or null` because its published
synthetic vectors predate DM-014. A non-DM-014 string remains valid identity
provenance but grants no species authority and cannot start an application
chain. Existing signed vectors and oracle behavior therefore remain unchanged.

## Cross-spec amendments

- DM-010: separates the species-maintainer key role, scopes its domain list to
  artifacts defined there, and records immutable enrollment provenance.
- DM-011: registers the exact DM-014 artifact/hash domains, wrapper ceilings,
  mergeable threshold families, and leaves its existing genesis wire field and
  vectors unchanged.
- DM-012: `/species` carriage evidence combines the release registry with the
  subject's ordered application chain; `.diff` uses the combined DM-014 cursor;
  non-current states never resolve as recipients.
- DM-013: freezes the typed release grammar while preserving
  context-incomplete/quarantine-only effects on species provenance.
- DM-018: now directly depends on DM-014 because adapter contracts consume its
  capability and content-manifest boundaries.
