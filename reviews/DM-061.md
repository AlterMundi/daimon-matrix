## Authority findings

- Release validity, compatibility and local application remain three separate
  decisions. Imported bytes, package metadata, CI, adapter output or
  maintainer text cannot activate code.
- Genesis and release zero require the declared threshold plus fresh
  possession by every initial maintainer. Successors use the exact predecessor
  policy; rotations require every resulting key and preserve immutable floors.
- Same-position or late siblings quarantine without an arrival, label, time,
  length or hash winner. Only the specialized next-epoch resolution with a
  complete content-addressed closure and fresh resulting-key possession closes
  a normal fork; old evidence and high-water remain durable.
- Compatibility is recomputed from predecessor-selected CAS bytes in pinned
  `wasmtime==45.0.0`, with fixed-zero time and no network, randomness,
  environment, devices, host write, child process or ambient authority.
- Existing carriers cannot apply an incompatible child in V0. Parent branch
  intent and child genesis custody use independent policies. A fresh DM-013
  newborn may enroll the exact child release without inheriting parent
  identity, memory, grants, membership or routes.

## Findings resolved during self-review

- Bundle limits were initially evaluated per dependency. The final verifier
  enforces aggregate file count, filesystem bytes, dependency depth/nodes and
  total closure bytes across the complete graph, closing a many-small-bundles
  bypass.
- Runtime code accepted V4 species configuration before a public V4 bundle
  schema existed. The closed schema now publishes the exact nullable species
  configuration, and a real authenticated preview test loads it.
- Early public species schemas left protocol deltas, fork resolution, incoming
  cursor/pages/conflicts and application predecessors too generic. They are
  now closed exact shapes; tests validate canonical genesis, releases, fork
  resolution, branch foundation/child and a real appended application payload.
- The content-reference schema allowed an arbitrary safe integer while runtime
  validation capped blobs at 64 MiB. Both now enforce `67108864` bytes.
- The synthetic entry point originally tolerated reused state and ordinary
  output writes. It now requires an empty owner-only state root and writes a
  fsynced atomic mode-`0600` report with bounded failure output.
- Full-suite validation exposed that the new application kind existed in the
  runtime enum but not the public DM-011 event schema. The schema now includes
  `matrix/species-release-application` and binds its payload to the DM-014
  application definition.
- Three new package modules changed content-bound Hermes package evidence. Only
  the deterministic DM-041 provenance/index/profile/launch artifacts changed;
  their generator reproduces them byte-identically.

## Durability and public boundary

- Incoming snapshots bind subject, immutable enrollment, effective
  application, accepted/greatest/closed cursors, occupied positions, selected
  candidate, missing/conflict evidence and complete content-bound pages. Paths
  beyond 64 releases remain ineligible until the terminal page is stored.
- Application rechecks policy, capability-set hash, snapshot pages, registry
  and application heads under an owner-local cross-process lock. The fsynced
  journal fences the pointer before appending one deterministic operational
  event; recovery rolls back a pre-event switch or completes an already
  durable event without replaying effects.
- A late sibling of serving code authors a new `release-fork` rollback event to
  the last previously applied unforked ancestor. It does not lower release
  evidence or rewrite `/me`, enrollment, event history or memory.
- The daemon, CLI and MCP expose five typed methods only. No public request
  carries database/CAS paths, pointer paths, private seeds, runner handles,
  package managers, credentials or raw authority state.
- The exact 124 DM-014 Section 14 rows are frozen as named scenario IDs and
  mapped to executable category matrices; CI fails if the spec rows, mapping,
  evidence methods or generated bytes drift.
