## Authority and privacy findings

- A source claim is attributed evidence, never truth, membership, identity,
  birth, species, route, disclosure, memory, `/we`, Tribe, host or Cluster
  authority.
- Each foreign being is verified against its exact root authority and stored
  in its own known ledger. The receiver's writable ledger authors only its own
  cursors, assessments and import decisions.
- Incoming is a write-free preview. Pull is an explicit owner-local operation,
  admits complete canonical evidence only to quarantine, and has no
  auto-promotion mode.
- Every current publication present anywhere in a selected-source origin
  closure is independently disclosure-authorized, carries complete current
  content/provenance, and receives its own receiver-authored import decision.
- Historical publication revisions and tombstoned heads retain signed metadata
  but never cause withdrawn content to be re-offered. A fresh receiver can land
  a tombstone without receiving those bytes.
- An incomplete item is reported but not persisted or represented as known in
  the achieved cursor, so a later complete response can offer it again.
- Interleaved events for another source require explicit `origin-closure`
  disclosure authorization, remain transport dependencies, and cannot create a
  selected-source assessment or import decision.
- Promotion is a later exact successor decision and can create only an
  attributed `external-reference`; external material cannot become
  autobiography or lived body experience.

## Findings resolved during self-review

- Preview-only `admissible-*` labels initially leaked into pull results. Pull
  now reports the normative `admitted-to-quarantine` outcome.
- Public source operations could race intake between threads/processes. All
  views and transitions now share a reentrant owner-only source lock.
- A republish after tombstone conflicted with the existing import series. It
  now creates a quarantine successor bound to the new publication event.
- A recomputed diff item could substitute claim/publication kind against the
  wrong series type. Runtime validation and the public schema bind them.
- A claim item could carry a publication transitively without a corresponding
  import decision. Pull now derives every current publication head across the
  complete selected-source closure and emits one exact receipt per head.
- Incomplete items were previously eligible to land and could become falsely
  known. They are now excluded from the landing set and remain retryable.
- Publication completeness initially demanded every historical revision's
  bytes, which could re-disclose withdrawn content. Only the exact current
  publish head carries content; tombstone metadata remains synchronizable.
- Bundled events lacked a proof that they belonged to the target lane's origin
  closure. The receiver now rejects unrelated signed-event injection while
  permitting only necessary predecessor/causal ancestors.
- Exact Section 13 depth/count/content/bundle ceilings, inert hostile content,
  assessment/publication forks and operation serialization lacked direct
  boundary evidence. Dedicated adversarial tests now cover each boundary.
- Wheel entry-point ordering and an unwanted newline disagreed with the exact
  installed fixture. The distribution check and entry point now compare exact
  canonical bytes.
- Adding package modules changed the content-bound DM-041 Hermes inventory.
  Its provenance, profile, launch receipt and vector index are regenerated
  from the final source inventory rather than hand-edited.
